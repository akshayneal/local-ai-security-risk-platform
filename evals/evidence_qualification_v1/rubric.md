# Prospective authored diagnostic rubric

Twelve new opaque cases; each is one authored engineering situation, not a random
sample or an independent human judgment. Development IDs/literals are disjoint.
The key is scorer-only and is never supplied to application functions.

Score five layers separately: exact extraction/original retention; source
eligibility/refusal; association; scoped comparison; report/export integrity.
Unavailable must never be scored as safe/legitimate. Native Microsoft opaque
ActionType is not synthetic completed operation semantics. A failed mismatch is
about attempted declared scope, not completed transfer. Missing, ambiguity and
conflict require explicit abstention; irrelevant identity cannot create a join.

The expected statuses/relationships are frozen author judgments with no accepted
post-hoc alternatives. Stable reason codes and retained source pointers supply
failure provenance; string status match alone is insufficient. Reports must
retain source hashes and complete original bytes, preserve scalar types, grant
no approval and execute no action, and recompute identically for JSON/Markdown.
Per-class denominators remain visible even when the class contains one case.

Freeze input/key/rubric/runner and candidate source hashes before the sole offline
diagnostic. Reserve with exclusive creation before reading diagnostic cases.
No retries, model calls, historical experiment reruns, hidden omissions or
post-exposure source/key changes. If interrupted, retain reservation and stop;
read-only inspection of saved results is allowed. Any failure remains in the
case-level report and blocks its gate; fixes require a new version and fresh
prospective evaluation. Human semantic adjudication and visual QA remain pending.
