# Sprint 9: controlled inference and evidence fidelity

Experimental development only. No release, new product capability, deployment
approval, independent adjudication or semantic reliability rate is claimed.

## Prospective question and controls

H1 tests application-owned structural reviewability and a finding-only generation
contract against the existing coverage union on identical synthetic lab graphs.
H2 tests an immutable, field-bound ledger against the same request without it.
H3 isolates workflow-specific instructions and, only if the installed provider
reports support, explicit thinking settings. H4 tests precise identity/state/source
contradictions where supplied fields are conclusive; arbitrary prose entailment
remains outside deterministic validation.

The separate acceptance cases/rubric/runner/accounting identities must be committed
before any generation or inspection of lab outcomes. Their author is Codex, so
they are prospective but neither blind nor independent. Historical cases, results,
scorers and judgments remain immutable. New lab cases may repeat and evolve with
each treatment fully identified; repeats never become acceptance observations.

## Budgets and stopping rules

One shared durable journal reserves and fsyncs each raw request before transport.
Caps: 24 lab, 12 acceptance, 36 total, with no borrowing. Every SDK retry, HTTP
request, repair and uncertain timeout counts. Sequential foreground only; no
warm-up, automatic resume, external provider or background generation. Outstanding
reservations, timeout/cancellation uncertainty, unexpected request, protected-byte
change, accounting fault or source-authority compromise stop inference.

## Engineering sequence and viability gate

1. Inventory/protection and baseline deterministic checks; no model calls.
2. Commit this plan, exact scope, fresh acceptance freeze and separate lab design.
3. Failing deterministic tests, compact technical contract, reviewability and
   narrow generation instructions; commit before lab inference.
4. Paired technical positive/benign lab baseline and treatment; isolate changes.
5. Add ledger and precise controls, run paired SOC/governance positive/negative
   lab cases; journal all attempts, failures, competing explanations and decisions.
6. Choose an implementation only if the latest treatment returns both technical
   positive and benign advisories, a specific conditional graph-bound finding for
   the positive and zero fabricated findings for the benign; latest SOC and
   governance controls must preserve their material facts with no observed high
   impact unsupported claim, evidence-state or scope reversal. This is an authored
   engineering viability judgment, not statistical proof. If unmet, acceptance is
   NOT RUN and its reserved allowance remains unused.
7. Commit the final implementation and freeze its runtime/source identity. Run
   acceptance once only. No semantic tuning or model-dependent fixes afterward.
   Report failures as follow-up blockers, with no replay or replacement holdout.
8. Full deterministic tests, Ruff, pip check, diff/protection checks; additive
   checkpoints and normal feature push, exact-final-SHA Actions inspection.

## Scope and responsibility

The exact allowlist is in `sprint9_preservation.json`; every other baseline path
must retain its Git blob identity. Python determines declared structural
reviewability, canonical request identity, field/row provenance and contract
membership. The model proposes hypotheses and review actions. Neither schemas,
field matches nor source membership establish entailment, deployed control status,
approval, safe operation or permission to execute actions.

Keep public request/response shapes, original endpoints, retrieval defaults,
Inspector/correction lineage, exports and launchers. No dependencies, launch
processes, OS settings, protected workspaces or historical evidence are changed.
Any historical test migration retains its unchanged original assertion/body at
the immutable Sprint 8 endpoint, plus current replacement coverage and negative
mutation proof. Do not widen an old scope guard.

## Required outcomes and handoff

The frozen acceptance rubric measures availability separately from usefulness,
fact retention/contradiction, candidate-risk/benign behavior, unknown/absence/
implemented polarity, narrow scope and citation relevance. Per-case, per-pillar
and control-type denominators must remain visible. Author judgments and software
checks are separate; independent semantic review and USER WORKFLOW / FINAL VISUAL
QA remain PENDING. Passing software checks or authored cases cannot authorize a
release. Start/final SHAs, all commands/counts/failures, protected sets, exact change
inventory and final CI evidence belong in the readout.
